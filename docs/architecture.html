Overview

PingBot is an asynchronous Telegram bot that monitors network hosts (IP or domain) via ICMP ping. It notifies users when connectivity status changes, tracks outage history, and provides per-host management controls.

Python 3.14 aiogram 3.x PostgreSQL 18 SQLAlchemy async Alembic icmplib Docker

Database Models

🖥 Host - table: hosts

Column Type Description
id Integer PK Auto-increment primary key
user_id BigInteger Telegram user ID of the owner
address String IPv4 or domain name to monitor
pretty_name String User-friendly display name
is_active Boolean Whether monitoring is running (can be paused)
status_up Boolean|NULL Last confirmed status. NULL = first check pending
last_change DateTime(tz) Timestamp of last confirmed status change

⚡ Outage - table: outages

Column Type Description
id Integer PK Auto-increment primary key
host_id FK → hosts.id Which host had the outage
offline_at DateTime(tz) When the host went DOWN (confirmed)
online_at DateTime(tz)|NULL When it came back UP. NULL = currently still down

An open outage record (online_at = NULL) means the host is currently considered DOWN.

User Flows

1. Add Host Flow (/add or ➕ button)

1
Trigger
User sends /add command or taps "➕ Додати адресу" reply button → cmd_add() / btn_add()
2
FSM: waiting_for_address
Bot replies "Enter IPv4 or domain". Cancel keyboard shown. State set to AddHostState.waiting_for_address
3
Validation - process_address()
is_valid_ipv4() checks 4 octets 0–255. is_valid_domain() checks RFC hostname pattern. On failure: re-prompt same state. On success: advance to waiting_for_name
4
FSM: waiting_for_name - process_name()
User enters a name (or sends anything - empty defaults to the address itself). Host saved to DB. Main menu keyboard restored.

2. Delete Host Flow (/delete or 🗑️ button)

1
Trigger
User sends /delete or taps "🗑️ Видалити адресу" → _show_delete_list(): sends each host card with full inline keyboard
2
Tap 🗑️ Видалити on a card - callback_delete_confirm()
The host card's inline keyboard is replaced with [✅ Так, видалити | ↩️ Назад]
3a
Confirm - callback_delete_execute()
Host deleted from DB via session.delete(host). Message text replaced with "🗑️ Name (address) видалено."
3b
Cancel - callback_delete_cancel()
Original host keyboard restored via edit_reply_markup(). No DB changes.

3. Rename Host Flow (✏️ inline button)

1
callback_rename()
Stores host_id in FSM data, sets state RenameState.waiting_for_name. Shows cancel keyboard.
2
process_new_name()
Reads new name (max 50 chars) from message, updates DB, restores main menu keyboard.

4. Background Monitoring Loop - run_monitoring()

1
Every 60 seconds
All is_active=True hosts fetched. Pings run in parallel via asyncio.gather() using check_host() (ICMP, count=2, timeout=2s)
2
First ping ever
status_up = NULL → silently set initial status, no notification sent.
3
Status unchanged
Result matches host.status_up → any pending counter is reset and discarded.
4
Status changed - counter starts
In-memory _pending_changes[host_id] = (new_status, count) tracks consecutive confirmations.
5
Threshold reached (STATUS_CHANGE_THRESHOLD)
DB updated (status_up, last_change). Outage record created/closed. Telegram notification sent via bot.send_message() with Markdown bold.

5. Cancel Flow (❌ Скасувати)

1
cmd_cancel()
Matches reply text "❌ Скасувати" at any FSM state. Clears state, restores main menu keyboard. Works for both AddHostState and RenameState.

Keyboard Architecture

Reply Keyboards (persistent bottom bar)

Function Shown When Buttons
get_main_menu_keyboard() Default / after any flow completes ➕ Додати адресу · 📋 Мій список · 🗑️ Видалити адресу
get_cancel_keyboard() During any active FSM state ❌ Скасувати

Inline Keyboards (per message)

Function Callback prefix Action
get_host_keyboard() check_ / toggle_ / rename_ / delete_confirm_ Per-host management card
get_delete_confirm_keyboard() delete_execute_ / delete_cancel_ Confirm/cancel deletion

Environment Variables

Variable Required Default Description
BOT_TOKEN required - Telegram bot token from @BotFather
DATABASE_URL required - SQLAlchemy async URL, e.g. postgresql+asyncpg://user:pass@db/dbname
POSTGRES_USER required - PostgreSQL username (used by docker-compose)
POSTGRES_PASSWORD required - PostgreSQL password
POSTGRES_DB required - PostgreSQL database name
TZ optional Europe/Kyiv IANA timezone for notification timestamps
STATUS_CHANGE_THRESHOLD optional 5 Consecutive pings before confirming status change (~minutes)
PGADMIN_DEFAULT_EMAIL pgadmin admin@svitlo.bot pgAdmin login email
PGADMIN_DEFAULT_PASSWORD pgadmin adminpassword pgAdmin login password

Testing

Tests run inside an isolated python:3.14-slim Docker container - same as CI/CD. A real SQLite tempfile is used instead of shared memory to avoid aiosqlite I/O locking issues.

File What it tests
test_database.py Host creation, query, Outage record creation and closing
test_handlers.py /start clears state, /add triggers FSM, address validation accepts/rejects inputs
test_monitor.py duration formatting, check_host ping mocking, counter accumulation, counter reset on recovery

Run locally

docker run --rm -v "${PWD}:/app" -w /app python:3.14-slim sh -c "pip install pipenv && pipenv install --dev && pipenv run pytest --cov=src tests -v"
