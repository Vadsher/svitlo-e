# PingBot 💡

Телеграм-бот для моніторингу доступності мережевих хостів (IP або DDNS) через ICMP ping. Сповіщає про зміну стану електроживлення (зникло/з'явилось) та рахує час відсутності.

> 🤖 **Офіційний бот:** Цей репозиторій містить оригінальний вихідний код, на якому працює бот [@custom_svitlo_e_bot](https://t.me/custom_svitlo_e_bot). Ви можете розгорнути власну версію за інструкціями нижче або скористатися вже готовим ботом у Telegram!

## Основні можливості
- 🖥️ **Зручний інтерфейс**: Інтерактивне меню з кнопками "➕ Додати адресу", "📋 Мій список", "⚙️ Налаштування" та "🗑️ Видалити адресу" для простого керування.
- 🛡️ **Валідація адрес**: Автоматична перевірка правильності введених IPv4-адрес та доменних імен.
- ⏱️ **Захист від хибних спрацювань**: Сповіщення про зміну статусу надсилаються лише після заданої кількості послідовних пінгів (змінна `STATUS_CHANGE_THRESHOLD`), що дозволяє ігнорувати короткочасні мережеві збої.
- ⏸️ **Гнучке керування**: Можливість тимчасово призупиняти моніторинг окремих хостів, перейменовувати або видаляти їх, а також виконувати миттєву перевірку статусу вручну.
- 👥 **Групові чати та Ролі**: Підтримка додавання бота в групові чати (наприклад, чат будинку або ЖК). Тільки адміністратори групи можуть налаштовувати бота (додавати/видаляти хости), тоді як усі учасники отримують сповіщення.
- 🏘️ **Комплексний моніторинг (Кластери)**: Об'єднання декількох IP-адрес в один логічний кластер (ввід через кому). Сповіщення "Світло вимкнено" надсилається лише якщо *всі* адреси кластера недоступні.
- 🔕 **Тихі години**: Налаштування тихих годин через команду `/settings` для уникнення нічних сповіщень.
- 📊 **Звіти за розкладом**: Бот автоматично формує та надсилає статистику відключень щодня, щотижня та щомісяця.

## 🚀 Заплановані фічі (Roadmap)
**🌍 Локалізація**
- Додати англійську локалізацію та вибір мови бота.

**📋 Покращення меню "Мій список"**
- Розділити логіку відображення залежно від кількості збережених адрес:
  1) **Декілька адрес**: Показати список адрес без кнопок. При натисканні на адресу відкривається меню із вибором дії (Перевірити / Пауза / Перейменувати / Видалити) та кнопкою "Назад".
  2) **Одна адреса**: Одразу показувати адресу зі списком дій.

**📊 Розширена статистика відключень**
У наступних оновленнях планується додавання потужної системи генерації звітів. Користувачі зможуть переглядати детальну статистику відсутності зв'язку/світла за різні періоди:
- За поточну добу (1 день) або за останні `n` днів
- За поточний чи минулий тиждень
- За поточний чи минулий місяць
- З обраної дати до сьогодні (наприклад: *від 01.12.2026 до сьогодні*)
- За точний проміжок часу (наприклад: *з 01.12.2026 по 31.12.2026*)

**⚡ Пакетні операції (Batch Operations)**
- Масове додавання кількох адрес за один раз
- Масове видалення кількох хостів одночасно

**🔒 Приватне налаштування груп (Private Setup Flow)**
- Перенесення процесу налаштування (команди `/settings`, `/add` та кроки FSM) в особисті повідомлення з ботом за допомогою Deep Linking. Це дозволить адміністраторам зручно керувати ботом, не засмічуючи загальний груповий чат службовими повідомленнями.

## Технологічний стек
- **Python 3.14**
- **aiogram 3.x**
- **PostgreSQL 18.4** (через asyncpg + SQLAlchemy)
- **Alembic** (міграції)
- **icmplib** (асинхронний ping без root-прав)
- **Docker & Docker Compose**

## Підготовка та Запуск

Всі конфігурації Docker та змінні середовища винесені у директорію `.ci-cd`.

1. Отримай токен бота у [@BotFather](https://t.me/BotFather).
2. Створи файл `.env` на основі шаблону:
```shell
cp ./.ci-cd/.env.example ./.ci-cd/.env
```

3. Відкрий `.env` та встав свій токен у змінну `BOT_TOKEN`.

### Ініціалізація бази даних (перший запуск)

Оскільки ми використовуємо Alembic, перед першим запуском бота потрібно згенерувати міграційні файли (переконайся, що знаходишся у кореневій папці репозиторію):

1. Запусти лише базу даних:
```shell
docker compose -f ./.ci-cd/docker-compose.yml up -d db
```

2. Згенеруй міграцію через тимчасовий контейнер бота (монтуємо папку, щоб файл зберігся на хості):
```shell
docker compose -f ./.ci-cd/docker-compose.yml run --rm -v ${PWD}/migrations:/app/migrations bot sh -c "alembic -c alembic/alembic.ini revision --autogenerate -m 'Initial setup'"
```
*Це створить файл міграції в папці `migrations/versions/` у корені репозиторію.*

### Деплой

Після створення міграцій підніми всі сервіси:
```shell
docker compose -f ./.ci-cd/docker-compose.yml up -d --build
```

Контейнер `bot` автоматично виконає `alembic upgrade head` перед стартом процесу, перевірить наявність змінних середовища та створить всі необхідні таблиці.

### Керування базою даних (pgAdmin)

Разом з ботом і базою даних піднімається сервіс **pgAdmin** для зручного керування базою через веб-інтерфейс.

1. Відкрий у браузері: `http://localhost:40880`
2. Авторизуйся за допомогою облікових даних, вказаних у твоєму `.env` файлі:
   - **Email**: значення `PGADMIN_DEFAULT_EMAIL` (за замовчуванням `admin@svitlo.bot`)
   - **Password**: значення `PGADMIN_DEFAULT_PASSWORD` (за замовчуванням `adminpassword`)
3. Щоб підключити базу даних PingBot у pgAdmin:
   - Натисни **Add New Server**
   - У вкладці **General** введіть будь-яке ім'я (наприклад, *Svitlo DB*)
   - У вкладці **Connection** введіть:
     - **Host name/address**: `db` (це внутрішнє ім'я контейнера)
     - **Port**: `5432`
     - **Maintenance database**: значення `POSTGRES_DB` (за замовчуванням `pingbot`)
     - **Username**: значення `POSTGRES_USER` (за замовчуванням `botuser`)
     - **Password**: значення `POSTGRES_PASSWORD` (за замовчуванням `botpassword`)


## Логування

Бот налаштований на вивід детальних логів у `stdout`. Для перегляду використовуй (перебуваючи в кореневій папці):
```shell
docker compose -f ./.ci-cd/docker-compose.yml logs -f bot
```

## Тестування

Проект використовує `pytest` для автоматизованого тестування та структурований чекліст для ручного QA.

### Ручне QA тестування
Для покрокової ручної перевірки функцій зверніться до [🧪 QA Testing Guide](QA_Checklist.ua.md). Цей посібник охоплює користувацькі сценарії, захист від спаму, тихі години та планування звітів.

### Автоматизоване тестування
Щоб запустити тести локально в чистому ізольованому контейнері `python:3.14-slim` (так само, як це відбувається у CI/CD), виконайте наступну команду з кореня репозиторію:

```shell
docker run --rm -v "${PWD}:/app" -w /app python:3.14-slim sh -c "pip install pipenv && pipenv install --dev && pipenv run pytest --cov=src tests -v"
```
